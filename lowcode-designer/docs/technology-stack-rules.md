# 低代码设计器框架技术栈规则

## 1. 核心技术栈

### 1.1 前端框架
- **React 18**：用于构建用户界面，提供组件化开发能力
- **TypeScript 5.6**：提供类型安全和更好的开发体验
- **Vite 6**：现代化的前端构建工具，提供快速的开发体验

### 1.2 UI 组件库
- **Ant Design 5**：企业级 UI 组件库，提供丰富的基础组件
- **amis 6.11**：低代码表单和页面渲染引擎，作为核心设计器能力
- **@ag-neptune/bu-ui**：自定义业务组件库

### 1.3 状态管理
- **MobX 4 + mobx-state-tree 3**：用于复杂状态管理，特别是设计器内部状态
- **Zustand 5**：轻量级状态管理，用于简单的全局状态共享

### 1.4 工具库
- **ahooks**：提供常用 React Hooks
- **axios**：HTTP 客户端，用于 API 请求
- **classnames**：CSS 类名管理
- **dayjs**：轻量级日期处理库
- **hotkeys-js**：键盘快捷键处理
- **immer**：不可变数据处理
- **lodash**：实用工具函数库
- **match-sorter**：数据排序
- **monaco-editor**：代码编辑器组件
- **sortablejs**：拖拽排序功能
- **tinycolor2**：颜色处理

## 2. 架构设计原则

### 2.1 组件化设计
- 采用**原子设计模式**，将组件分为原子组件、分子组件、有机体组件和模板组件
- 组件应具有良好的封装性和复用性
- 组件通信应遵循单向数据流原则

### 2.2 状态管理
- 设计器核心状态使用 **MobX + mobx-state-tree** 管理
- 全局共享状态使用 **Zustand** 管理
- 组件内部状态使用 React Hooks

### 2.3 代码组织
- 按功能模块划分目录结构
- 核心逻辑与 UI 分离
- 采用 TypeScript 严格类型检查

## 3. 开发规范

### 3.1 代码风格
- 使用 ESLint 进行代码质量检查
- 使用 Prettier 进行代码格式化
- 使用 Stylelint 进行样式检查
- 遵循 TypeScript 最佳实践

### 3.2 组件开发
- 函数式组件优先
- 使用 React Hooks
- 合理使用 TypeScript 泛型和接口
- 组件命名采用 PascalCase
- 文件命名采用 kebab-case

### 3.3 状态管理
- 复杂状态使用 MobX-State-Tree 的模型定义
- 简单状态使用 React Hooks（useState, useReducer）
- 全局状态使用 Zustand

### 3.4 API 设计
- 采用 RESTful API 设计规范
- 使用 axios 进行 HTTP 请求
- 统一错误处理机制

## 4. 性能优化

### 4.1 渲染优化
- 使用 React.memo 优化组件渲染
- 合理使用 useMemo 和 useCallback
- 避免不必要的重渲染

### 4.2 资源优化
- 按需加载组件和资源
- 优化图片和静态资源
- 使用 Vite 构建优化

### 4.3 状态优化
- 合理拆分状态，避免状态过大
- 状态更新应精细化，避免全量更新

## 6. 安全规范

### 6.1 数据安全
- 敏感数据加密存储
- API 请求添加身份验证
- 防止 XSS 和 CSRF 攻击

### 6.2 代码安全
- 避免使用不安全的依赖
- 定期更新依赖包
- 遵循最小权限原则

## 7. 部署策略

### 7.1 构建流程
- 使用 Vite 进行构建
- 生成环境变量注入
- 代码压缩和优化

### 7.2 部署方式
- Docker 容器化部署
- 支持多环境配置（开发、测试、生产）
- CI/CD 自动化部署

## 8. 扩展机制

### 8.1 插件系统
- 设计器应支持插件扩展
- 提供清晰的插件 API
- 支持动态加载插件

### 8.2 自定义组件
- 允许用户扩展自定义组件
- 提供组件注册机制
- 支持组件预览和配置

## 9. 版本控制

### 9.1 版本管理
- 使用语义化版本控制
- 定期发布 CHANGELOG
- 遵循 git-flow 工作流

### 9.2 分支管理
- main 分支：稳定版本
- develop 分支：开发版本
- feature/* 分支：新功能开发
- hotfix/* 分支：紧急修复

## 10. 文档规范

### 10.1 代码文档
- 关键函数和组件添加 JSDoc 注释
- 使用 TypeScript 类型定义代替文档
- 复杂逻辑添加必要的注释

### 10.2 项目文档
- 架构设计文档
- 开发指南
- API 文档
- 部署文档

## 总结

本技术栈规则旨在为低代码设计器框架提供统一的技术选型和开发规范，确保项目的可维护性、扩展性和性能。所有开发人员在进行设计器开发时应严格遵循本规则，以保证项目的质量和一致性。
