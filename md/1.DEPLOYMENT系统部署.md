# 部署文档

## 1. 项目概述

Soybean Admin NestJS 是一个基于 NestJS 构建的前后端分离管理系统，包含以下主要服务：
- 前端（frontend）：基于 Vue3 的管理系统界面
- 低代码设计器（lowcode-designer）：可视化低代码开发工具
- 后端（backend）：基于 NestJS 的 API 服务
- 数据库（postgres）：PostgreSQL 数据库
- 连接池（pgbouncer）：PostgreSQL 连接池
- 缓存（redis）：Redis 缓存服务

## 3. 本地部署

### 3.1 环境要求

- Node.js >= 18.x
- PostgreSQL >= 16.x
- Redis >= 7.x
- Git

### 3.2 部署步骤

#### 1. 克隆代码

```bash
git clone <repository-url>
cd soybean-admin-nestjs
```

#### 2. 启动外部服务

**PostgreSQL**：
```bash
# 启动 PostgreSQL 服务
# 确保端口为 25432，用户为 soybean，密码为 soybean@123.
# 创建数据库 soybean-admin-nest-backend
```

**Redis**：
```bash
# 启动 Redis 服务
# 确保端口为 26379，密码为 123456
redis-server --requirepass 123456 --port 26379
```

**Pgbouncer (可选)**：
```bash
# 如果使用 pgbouncer，启动 pgbouncer 服务
# 配置文件路径：deploy/pgbouncer/pgbouncer.ini
# 用户列表：deploy/pgbouncer/userlist.txt
pgbouncer deploy/pgbouncer/pgbouncer.ini
```

#### 3. 后端部署

**安装依赖**：
```bash
cd backend
npm install
```

**数据库迁移**：
```bash
npm run prisma:migrate
```

**启动服务**：

- 开发环境：
  ```bash
  npm run start:dev
  ```

- 生产环境：
  ```bash
  npm run build
  npm run start:prod
  ```

- PM2 生产环境：
  ```bash
  npm run build
  npm run pm2:start:prod
  ```

#### 4. 前端部署

**安装依赖**：
```bash
cd ../frontend
npm install
```

**构建生产版本**：
```bash

```

**本地预览**：

## 4. Docker 部署

### 4.1 环境要求

- Docker >= 20.x
- Docker Compose >= 2.x

### 4.2 部署步骤

#### 1. 克隆代码

```bash
git clone <repository-url>
cd soybean-admin-nestjs
```

#### 2. 配置数据库连接方式

**默认配置**：直接连接 PostgreSQL（推荐用于开发环境或小规模部署）

**启用 pgbouncer 连接池（可选，推荐生产环境）**：
1. 修改 `docker-compose.yml` 中的 `DATABASE_URL` 环境变量：
   ```yaml
   # 从直接连接改为 pgbouncer 连接
   DATABASE_URL: 'postgresql://soybean:soybean@123.@pgbouncer:6432/soybean-admin-nest-backend?schema=public'
   ```

#### 3. 启动所有服务

**使用 Docker Compose 一键启动**：
```bash
docker-compose up -d
```

**查看服务状态**：
```bash
docker-compose ps
```

#### 4. 访问服务

- 前端：http://localhost:9527
- 低代码设计器：http://localhost:9555
- 后端 API：http://localhost:9528
- Swagger 文档：http://localhost:9528/api-docs

#### 5. 常用 Docker 命令

**停止所有服务**：
```bash
docker-compose down
```

**重启单个服务**：
```bash
docker-compose restart <service-name>
```

**查看服务日志**：
```bash
docker-compose logs -f <service-name>
```

### 5.2 Pgbouncer 配置（可选）

Pgbouncer 是一个 PostgreSQL 连接池，用于优化数据库连接管理，推荐在生产环境或高并发场景下使用。

**配置文件**：`deploy/pgbouncer/pgbouncer.ini`

主要配置项：
- `listen_port`: 6432
- `auth_type`: md5
- `pool_mode`: transaction
- `max_client_conn`: 100
- `default_pool_size`: 20

**用户列表**：`deploy/pgbouncer/userlist.txt`
```
"soybean" "soybean@123."
```

**使用场景**：
- 生产环境部署
- 高并发访问场景
- 需要优化数据库连接管理

**启用方式**：
1. 本地部署：启动 pgbouncer 服务并修改 `.env` 中的 `DATABASE_URL`
2. Docker 部署：修改 `docker-compose.yml` 中的 `DATABASE_URL` 为 pgbouncer 连接

**禁用方式**：
1. 本地部署：不启动 pgbouncer 服务，使用默认的直接连接
2. Docker 部署：保持 `docker-compose.yml` 中的默认直接连接配置

**注意事项**：
- pgbouncer 容器默认会启动，但只有在配置了相应的 `DATABASE_URL` 时才会被使用
- 直接连接和 pgbouncer 连接可以根据部署规模和需求灵活切换

## 6. 故障排查

### 6.1 数据库连接问题

- 检查数据库服务是否正常运行
- 检查数据库连接 URL 是否正确
- 检查防火墙设置
- 对于 pgbouncer 连接，确保 pgbouncer 服务正常运行

### 6.2 Redis 连接问题

- 检查 Redis 服务是否正常运行
- 检查 Redis 密码是否正确
- 检查 Redis 端口是否正确

### 6.3 服务启动失败

- 查看服务日志获取详细错误信息
- 检查依赖是否安装完整
- 检查配置文件是否正确
