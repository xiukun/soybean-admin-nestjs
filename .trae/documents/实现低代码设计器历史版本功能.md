# 低代码设计器历史版本功能实现方案

## 1. 现状分析

### 1.1 后端实现
- ✅ 已存在 `LowcodePage` 和 `LowcodePageVersion` 实体
- ✅ 已实现版本创建、查询等核心功能
- ✅ 保存接口 `/v1/lowcode/pages/menu/{menuId}/save` 会自动创建新版本
- ✅ 提供版本查询接口 `/lowcode/pages/:id/versions`
- ✅ 提供手动创建版本接口 `POST /lowcode/pages/:id/versions`

### 1.2 前端设计器实现
- ✅ 已存在左侧版本管理面板 `LeftVersionsManage`
- ❌ 当前使用旧接口 `/system/amisPage/findHistory`，需切换到新接口
- ✅ 版本回滚功能基本实现，但需适配新数据结构

### 1.3 管理端实现
- ❌ 未实现低代码页面版本管理功能
- ❌ 缺少版本列表展示、回滚和管理功能

## 2. 实现方案

### 2.1 设计器端改进

**修改版本管理插件**：
- 文件：`lowcode-designer/src/designer/plugins/plugin-left-versions-manage/plugin.tsx`
- 将版本查询接口从旧的 `amisPageFindHistoryListById` 切换到新的后端接口
- 使用新的 API 调用方式获取版本列表
- 适配新的数据结构展示版本信息

**改进版本回滚功能**：
- 实现通过版本 ID 获取完整 schema 并替换当前设计的功能
- 确保回滚操作的安全性和用户体验

### 2.2 管理端实现

**添加版本管理页面**：
- 在管理端低代码页面列表中添加版本管理入口
- 实现版本列表展示，包含版本号、创建时间、创建人、变更日志等信息
- 实现版本回滚功能，允许将页面恢复到指定版本
- 实现版本删除功能（可选，需考虑版本依赖关系）

**集成版本管理 API**：
- 调用 `/lowcode/pages/:id/versions` 获取版本列表
- 调用 `/lowcode/pages/:id/versions` 手动创建版本
- 实现版本比较功能，直观展示版本间差异

### 2.3 数据结构适配

**设计器端数据结构**：
- 适配新的版本数据结构，包含 `id`、`version`、`changelog`、`createdAt`、`createdBy` 等字段
- 确保版本回滚时正确处理 schema 数据

**管理端数据结构**：
- 设计清晰的版本列表展示结构
- 实现版本差异比较的数据展示方式

### 2.4 种子数据实现

**添加Prisma种子数据**：
- 文件：`backend/prisma/seed.ts`
- 添加低代码页面版本管理表的种子数据
- 确保种子数据与实际业务逻辑一致
- 包含示例页面和版本数据

**Docker配置同步**：
- 更新 `docker-compose.yml` 配置，确保数据库初始化时包含种子数据
- 同步相关环境变量配置
- 确保Docker构建和运行时的数据一致性
