# 产品版本管理设计需求文件

## 1. 功能概述
产品版本管理模块用于管理产品的发布版本，支持版本的创建、编辑、查看、启用和禁用等操作，确保同一时间只有一个启用版本。

## 2. 功能需求

### 2.1 版本列表管理
- **功能点1.1**：展示产品版本列表，包含版本名称、版本号、状态、发布人、发布时间等信息
- **功能点1.2**：支持按版本号进行搜索
- **功能点1.3**：支持分页展示
- **功能点1.4**：支持版本数据的刷新

### 2.2 版本生命周期管理
- **功能点2.1**：新增版本
  - 支持填写版本名称、版本号、描述
  - 新增版本默认状态为关闭
  - 表单验证：版本名称和版本号为必填项

- **功能点2.2**：编辑版本
  - 支持修改版本名称、版本号、描述
  - 不允许修改已启用版本的状态

- **功能点2.3**：查看版本详情
  - 只读模式展示版本完整信息
  - 包含版本名称、版本号、状态、发布人、发布时间、描述等

- **功能点2.4**：启用版本
  - 同一时间只能有一个启用版本
  - 启用新版本时，自动将其他版本设为关闭
  - 提供确认提示，防止误操作

### 2.3 权限管理
- **功能点3.1**：仅管理员角色可进行版本管理操作
- **功能点3.2**：操作日志记录，包括新增、编辑、启用等操作

## 3. 非功能需求

### 3.1 性能要求
- 列表加载时间 ≤ 2秒
- 操作响应时间 ≤ 1秒

### 3.2 可靠性要求
- 数据持久化存储
- 操作失败时提供明确的错误提示

### 3.3 安全性要求
- 防止SQL注入
- 防止XSS攻击
- 接口权限验证


## 5. 接口设计

### 5.1 查询版本列表
- **URL**：
- **Method**：POST
- **Request**：{ "versionNum": "" }
- **Response**：{ "options": [], "total": 0 }

### 5.2 新增版本
- **URL**：
- **Method**：POST
- **Request**：{ "versionName": "", "versionNum": "", "description": "" }
- **Response**：{ "success": true, "msg": "保存成功" }

### 5.3 编辑版本
- **URL**：
- **Method**：POST
- **Request**：{ "id": "", "versionName": "", "versionNum": "", "description": "" }
- **Response**：{ "success": true, "msg": "更新成功" }

### 5.4 启用版本
- **URL**：
- **Method**：POST
- **Request**：{ "id": "" }
- **Response**：{ "success": true, "msg": "启用成功" }

## 6. 页面设计

### 6.1 版本列表页面
- **布局**：顶部搜索栏 + 中间操作按钮 + 底部表格
- **操作按钮**：新建版本
- **表格列**：版本名称、版本号、状态、发布人、发布时间、操作
- **操作列**：修改、详情、启用（仅对关闭状态版本显示）

### 6.2 版本新增/编辑弹窗
- **表单字段**：版本名称、版本号、描述
- **按钮**：保存、取消

### 6.3 版本详情弹窗
- **只读展示**：版本名称、版本号、状态、发布人、发布时间、描述
- **按钮**：关闭

## 7. 业务规则

### 7.1 版本状态规则
- 新增版本默认为关闭状态
- 同一时间只能有一个启用版本
- 可以编辑已关闭版本的信息
- 不能直接编辑已启用版本的状态

### 7.2 版本号规则
- 版本号格式建议采用语义化版本号（如：1.0.0）
- 版本号唯一，不允许重复


### 8.2 性能优化
- **建议1**：添加版本列表缓存，减少数据库查询次数
- **建议2**：优化分页查询，提高大数据量下的查询性能

### 8.3 用户体验优化
- **建议1**：添加版本号自动生成功能，根据当前版本自动生成下一个版本号
- **建议2**：添加版本状态变更的消息通知
- **建议3**：优化表单验证，提供更友好的错误提示


## 9. 验收标准

### 9.1 功能验收
- 能够成功新增、编辑、查看、启用版本
- 同一时间只能有一个启用版本
- 搜索功能正常工作
- 表单验证有效

### 9.2 性能验收
- 列表加载时间 ≤ 2秒
- 操作响应时间 ≤ 1秒

### 9.3 兼容性验收
- 支持主流浏览器：Chrome、Firefox、Safari、Edge
- 支持不同屏幕尺寸

### 9.4 安全性验收
- 防止SQL注入
- 防止XSS攻击
- 接口权限验证有效

# 历史页面管理设计需求文件

## 1. 功能概述
历史页面管理模块用于管理页面功能的历史版本，支持查看历史版本，便于追溯页面功能的变更历史。 通过查看跳转到设计器的设计页面，我们通过历史版本查看这个页面的历史。

## 2. 功能需求

### 2.1 历史版本列表管理
- **功能点1.1**：展示页面功能的历史版本列表，包含菜单页面、页面版本、创建时间、创建人等信息
- **功能点1.2**：支持按菜单页面和页面版本进行筛选
- **功能点1.3**：支持分页展示
- **功能点1.4**：支持历史版本数据的刷新

### 2.2 历史版本操作
- **功能点2.1**：查看旧版本页面
  - 支持在新窗口打开旧版本页面
  - 只读模式，不允许编辑

- **功能点2.2**：删除历史版本
  - 支持单个删除
  - 支持批量删除
  - 删除前提供确认提示

### 2.3 权限管理
- **功能点3.1**：仅管理员和开发人员角色可进行历史版本管理操作
- **功能点3.2**：操作日志记录，包括删除等操作

## 3. 非功能需求

### 3.1 性能要求
- 列表加载时间 ≤ 2秒
- 操作响应时间 ≤ 1秒

### 3.2 可靠性要求
- 数据持久化存储
- 操作失败时提供明确的错误提示

### 3.3 安全性要求
- 防止SQL注入
- 防止XSS攻击
- 接口权限验证



## 5. 接口设计

### 5.1 查询历史版本列表
- **URL**：
- **Method**：POST
- **Request**：{ "mainId": "", "versionNum": "", "pageNum": 1, "pageSize": 10 }
- **Response**：{ "options": [], "total": 0 }

## 6. 页面设计

### 6.1 历史版本列表页面

- **筛选条件**：菜单页面（树形选择）、页面版本（下拉选择）
- **操作按钮**：批量删除
- **表格列**：菜单页面、页面版本、创建时间、创建人、操作
- **操作列**：查看页面、删除

## 7. 业务规则

### 7.1 历史版本规则
- 按菜单页面组织版本历史
- 每个页面可以有多个历史版本
- 历史版本记录页面功能的变更
